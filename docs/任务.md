### 当前卡点与下一步（2026-11-20 晚，重要进展）

**两个关键发现**

1. **`FAKE_DEV=1` 之前一直没设**。`h_gcd` 默认透传真 SetupAPI 枚举，只有显式 `FAKE_DEV=1`

### cm 列的最后定位（2026-11-20 17:30）

**倍率的真实来源已确认**（不再是我早先猜的 80）：

```
[0x523170] = 252000   ← 25.2 x 10000      (a.tw3d2 第 1 行)
[0x523190] = 18000    ← 1.8  x 10000      (a.tw3d2 第 1 行)
[0x5230fc] = 11                            (第 1 行)
[0x5230f4] = 13                            (第 1 行)
```

即装载器在 `0x5114D1..0x51151A` 按顺序从工程数据里读：double、int、int、double，
各自 x10000 存进全局。**全部来自 .tw3d2，与狗无关，也不需要写死。**

`0x513A30` 的入口结构：

```
fild qword [0x5231a8] / 与 0 比较 -> 相等则退出   (门槛1, 运行值 3000000)
fild qword [0x5231b0] / 与 0 比较 -> 相等则退出   (门槛2, 运行值 1500000)
movzx ecx, word [0x52315c]        ; 行号（唯一写入者 0x50311A，初始化设为 3）
mov edx, 2                        ; 列 = Offset
call 0x48d5b8                     ; 读该格
cmp dword [ebp-8], 0
je 0x513bdf                       ; 读到空就整函数退出
```

实测：即使把调用点挪到 Offset 循环之后（`0x511AFA`，已确认执行，ebx=0x20），
cm 仍写出 32 个 0。说明它内部取到的操作数还是空/零。

## cm 的完整机制

```
A = 网格(行来自 [ebx+0x530] 对象, 列2=Offset)
B = 网格(行 = [0x52315c] - esi, 列2=Offset)
cm = round((B - A) x 100 x g4 / 10000) / 100
常量：0x513C50 = 100.0，0x513C54 = 10000.0，0x513C40 = 25400.0
g4 = (25400/3000000) x [0x523074] / 1500000 x [0x523190]
```

实测：`[0x523074] = 25400 x 31 = 787400` 时 g4 = 79.99984 ≈ 80，与参考一致。
`[0x52315c]` 默认 3（唯一写入者 `0x50311A`），改成 32 后 cm 仍写 32 个 0。

即：**A 与 B 读到同一格**（差值为 0）。`[ebx+0x530]` 对象存在（实测 `0x260B454`），
但取出的行号让 A 恒等于 B，说明它内部的“基准行”尚未被填充。

**结论**：cm 只差一个“基准行”的数据源；倍率、行号、调用时机、函数逻辑都已排除。
