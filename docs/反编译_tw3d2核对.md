## 3. 两个原文档未记录的细节（A 级）

### 3.1 块头的第 4 个字段是「点数 − 1」

原文档把曲线块写作 `<图层> <分组> <子序号> <点数>` + 坐标行，实测**坐标行的数字个数
是 `2 × (点数 + 1)`**，即实际有 **点数+1 个坐标对**。

例（`3d2.tw3d2`）：

```
行 33:  6 0 0 17        ← 声明 17 点
行 34:  36 个数字        ← 即 18 对 = 17 + 1
行 35:  6 2 0 16        ← 声明 16 点
行 36:  34 个数字        ← 即 17 对 = 16 + 1
```

**全样本统计：278 个曲线块，278 个符合 `2 × (点数 + 1)`，无一例外。**

写回时若按「点数」个坐标对输出，会少一对点，文件与原始不再逐字节一致。

### 3.2 坐标行以 `\r\r\n` 结尾，其它行以 `\r\n` 结尾

`3d2.tw3d2` 里有 20 处 `\r\r\n`，全部落在**曲线坐标行**的末尾，
块头行与其它行都是单 `\r\n`：

```
b'6 246 412 242 419 252 419 252 \r\r\n6 2 …'
                              ↑ 额外的一个 CR
```

**全样本统计：278 个曲线块的坐标行全部带这个额外 CR，0 例外。**

各文件的 `\r\r\n` 计数：

| 文件 | CRLF 总数 | 其中 `\r\r\n` |
|---|---:|---:|
| `3d2.tw3d2` | 72 | 20 |
| `psdsampleCMYK.tw3d2` | 52 | 12 |
| `kelex.tw3d2` | 458 | 196 |
| `3danimation.tw3d2` | 32 | 0（无曲线块） |
| `donghua.tw3d2` | 32 | 0（无曲线块） |
| `flip3x.tw3d2` | 14 | 0（无曲线块） |
| `MorphZoomRatation.tw3d2` | 60 | 0（无曲线块） |

**含义**：按 `\r\n` 直接 split 会把坐标行读成「末尾多一个 `\r`」；
按 `\r\n` 回写则丢失这个字节。要做到逐字节无损，必须把「坐标行 = 内容 + `\r` + `\r\n`」建模。

> 这一条不影响解析出的**数值**（多出来的 `\r` 会被 strip 掉），只影响**字节级回写**。
> 原文档那句「12/12 逐字节无损回写」如果成立，说明它用的工具已经处理了这一点，
> 但布局表里没有写明这条规则，别人照表实现就会踩坑。

## 3.3 两条细节在代码里的成因（A 级，第 30 轮补）

上述两条不是「文件里碰巧如此」，而是**写入函数的显式行为**。
写入函数是 `0x510C54`（`_analysis/dump_psdto3d101_f/00510c54.c`，335 行）。

### 3.3.1 为什么是 `2×(点数+1)`

坐标行的发射循环（行 285–306）每轮写两个整数（X、Y），各带一个尾随空格：

```c
append_int(X - DAT_005232ec);  append_char(' ');
append_int(Y - DAT_005232f0);  append_char(' ');
} while (iVar4 != 0);          // iVar4 从「点数+1」开始倒数
```

循环次数就是 `点数+1`，所以数字个数 = `2×(点数+1)`、且**行尾总有一个空格**。

顺带一个发现：坐标写入的是 **`X − DAT_005232ec`、`Y − DAT_005232f0`**，
即相对某个原点偏移后的值（很可能是包围盒左上角）。

### 3.3.2 为什么是 `\r\r\n`

坐标行写完后连续两行（308–309）：

```c
puVar1 = FUN_00403774(buf, 0x0d);   // 显式追加一个 CR
FUN_00403870(puVar1, …);            // 再追加行终止符
```

而行终止符 `FUN_00403870` 自身按标志位二选一（25 行，已读全）：

```c
if ((param_1[6] & 1) == 0) { 追加 0x0A（LF，1 字节） }
else                       { 追加 0x0D0A（CRLF，2 字节） }
```

本工程走的是 else 分支 → **CR + CRLF = `\r\r\n`**。

其它行只调用行终止符（12 处），所以是单 `\r\n`。

**这就把第 3.1、3.2 节的实测现象解释干净了**：
文件字节（实测）与写入代码（静态）两边对得上。

## 5. 复现

```bash
python - <<'PY'
import re
from pathlib import Path
NUM = re.compile(rb'^-?\d+$')
tot = ok = 0
for base in ('Psdto3d/sample', 'Psdto3d (2)/sample'):
    for f in Path(base).glob('*.tw3d2'):
        parts = f.read_bytes().split(b'\r\n')
        i = 8
        while i < len(parts) - 1:
            core = parts[i][:-1] if parts[i].endswith(b'\r') else parts[i]
            toks = core.strip().split()
            if len(toks) == 4 and all(NUM.match(t) for t in toks):
                npts = int(toks[3])
                nxt = parts[i + 1]
                ncore = nxt[:-1] if nxt.endswith(b'\r') else nxt
                ct = ncore.strip().split()
                tot += 1
                if len(ct) == 2 * (npts + 1) and nxt.endswith(b'\r'):
                    ok += 1
                i += 2
                continue
            i += 1
print('曲线块 %d，符合「2*(点数+1) 且带 CR」%d' % (tot, ok))
PY
# 期望输出：曲线块 278，符合「2*(点数+1) 且带 CR」278
```

## 机械验证结果（第 53 轮，A 级）

写了 `_analysis/check_tw3d2.py`，对仓库里**全部 504 个 `.tw3d2`**（跳过 `_work/v*`）
机械核对 6 条不变量：

| 断言 | 含义 | 违规文件数 |
|---|---|---:|
| T1 | GBK 编码且无 BOM | **0** |
| T2 | 行尾 CRLF、无裸 LF | **0** |
| T3 | 含 `99100` 魔数行 | **0** |
| T4 | 曲线坐标行带额外 CR（`\r\r\n`） | **0** |
| T5 | 额外 CR 行的数字个数为偶数 | **0** |
| T6 | 无定点小数（统一科学计数法） | **0** |

**通过率 504 / 504 = 100.0%。**

### 一个重要澄清：`\r\r\n` 不是每个文件都有

504 个文件里：

| 类别 | 数量 |
|---|---:|
| 含曲线块（有 `\r\r\n` 坐标行） | **200** |
| 不含多点曲线（自然没有这种行） | **304** |

初版检查器把「没有 `\r\r\n`」当成违规，误报了 304 个文件。
实际这是**数据的性质**，不是格式违规——没有多点曲线的工程自然不产生坐标行。

**结论**：`\r\r\n` 是「曲线坐标行」的标记，只出现在含曲线的文件里；
读侧必须容忍两种文件都存在。

### 另一处误报

T6 初版把第一行路径里的 `10.1`（`psdto3d10.1绿色版`）当成定点小数，误报 15 个文件。
修正为跳过首行（原始 PSD 路径）与路径样式的行后归零。
