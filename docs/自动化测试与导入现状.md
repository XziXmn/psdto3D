# 自动化测试（无人工输入）与当前导入现状

> 归档。驱动脚本还能用，任务状态不要从这里读。见 [任务.md](任务.md)。

目标：不用任何鼠标/键盘，也能把「导入 PSD → 生成 → 导出 TIFF」跑通并验证产物。
本目录的 `tools\` 已经做到**无人值守驱动**，同时也暴露了一个原有 bug。

---

## 1. 为什么需要专门做"无输入驱动"

这台机器上的会话没有前台窗口（`GetForegroundWindow() == 0`），任何 `SendInput` /
`keybd_event` 都投递不到目标窗口，标准文件对话框也无法用 `WM_COMMAND` 关闭
（`tools\dialog_probe.py` 试了 6 种消息法，全部无效）。因此改成**绕开对话框**：

`tools\dialogless_launch.py`
1. 正常 `CreateProcess` 启动，等主窗体出现；
2. `VirtualAllocEx` 分配 1 页 RWX，写入两个桩（stub）与各自的路径/文件名；
3. 把 `comdlg32!GetOpenFileNameA` / `GetSaveFileNameA` 的 **IAT 槽**改指向桩；
4. 桩把 `OPENFILENAME.lpstrFile / nFileOffset / nFileExtension / lpstrFileTitle`
   全部填好并返回 `TRUE`。

关键点：这个 exe 的 `OriginalFirstThunk == 0`，IAT 同时充当导入查找表；
在加载器运行**之前**改 IAT 会让进程以 `0xC0000139 (STATUS_ENTRYPOINT_NOT_FOUND)`
直接退出。所以必须"先启动、后打补丁"。

`tools\run_e2e.py` 在此之上按菜单命令驱动：`3` 打开工程 / `7` 导入 PSD /
`12` 预览 / `16` 导出 TIFF，自动点掉所有 `TMessageForm`，最后校验产物
（TIFF 魔数 + IFD 里的宽高/位深/压缩/采样数）。

`tools\trace_exception.py` / `trace_after_stub.py` 以最小调试器身份挂上去，
记录每一次异常的代码、地址、所属模块与偏移。

## 2. 已经跑通的部分

* 无输入驱动**成立**：app 收到 `WM_COMMAND` 后会实际执行菜单命令；
  文件对话框被桩替代，路径确实生效（例如 10.1 版导入时在
  `C:\ok3dtemp\` 下写出了 `lyt1.gjs … lyt12.gjs` 共 12 个每层数据文件）。
* 绿色版的授权闸门、UAC、4GB 标记均未参与失败（三套构建表现一致）。
* 自动点掉消息框、截图留证、异常追踪均可用。

## 3. 现在的失败点（重要）

导入/打开工程时，程序在**读取完 PSD 之后**抛异常：

```
模块   psdto3d101.exe
RVA    0x101093        （2022 版；VA 0x501093）
代码    mov edx,[edx+ecx*4]      ; edx = 组表项指针, ecx = [0x523158]
异常    C0000005 读 0x020007D0   （edx 已是野指针）
```

上游指令：

```
0050106a  movzx eax, byte [edx+eax*8+0x2c]   ; 图层记录里的分组号
0050106f  test  ax,ax  / je skip  / cmp ax,0x64 / cmp ax,0xff
00501083  mov   ecx,[0x52309c]               ; 组表（按最大分组号开）
00501089  mov   edx,[ecx+edx*4-4]            ; ← 表项；表未建立时这里是垃圾
0050108d  mov   ecx,[0x523158]               ; 索引
00501093  mov   edx,[edx+ecx*4]              ; ← 崩
```

异常被 `0x5048F3` 的 SEH 分支捕获，于是弹出
`All layers must be simple layer, Can not have backgroup layer!` —— 这条文案是
**导入失败的总兜底提示**，并不是真的在判断"背景层"。证据：把素材里名为
`Background` 的图层改名（`tools\psdrename.py`）后，报错一字不差。

三套构建的表现：

| 构建 | 导入 PSD | 说明 |
|---|---|---|
| 2022 绿色版 | 抛 `0x101093` 异常 → 弹提示 | 异常重复上万次 |
| 10.1 绿色版 | 写出 12 个 `lyt*.gjs` 后同样弹提示 | 说明 PSD 已被解析到图层级 |
| 99 绿色版（原厂） | 状态栏显示 `Layers: 3`、`Size 0x0` | 部分解析 |

结论：**这不是授权、UAC、64 位或我打的两个补丁引起的**，而是三个版本共有的
导入实现问题；`0x523158` 这个索引与组表状态不匹配时就会崩。

## 4. 素材侧的事实（已核）

`tools\psdlayers.py` 解析出的图层记录：

* `3d2.psd`：12 层，第 0 层名字就是 **`Background`**，其余为 `1..9`；
* `3danimation.psd`：12 层，名字为 `图层 46 / 图层 26 / 图层 29…38`；
* 两个绿色包内 12 个 sample 工程的图层分组已致密化为 `{1}`（见 `tw3d2.py regroup`）。

## 5. 下一步（需要一份"你那边能成功导入"的素材）

自动化链路已经就绪，缺的是**参照物**：只要有一份在你机器上能正常导入并出图的
PSD（或工程 + PSD），我就能：

1. 用同一套桩把这份素材喂给绿色版，确认链路走通、导出 TIFF；
2. 对比它能过而 sample 过不了的原因（层名/分组/尺寸/通道数/位深）；
3. 再决定是"转素材"（`psdrename`/`regroup` 这类工具）还是"补丁化"导入路径。

复现命令：

```powershell
# 无输入跑一遍：导入 → 预览 → 导出
python tools\run_e2e.py --pkg "psdto3d2022绿色版" --project "_test\3d2_nobg.psd" `
       --out "_test\out.tif" --commands import=7,preview=12,tiff=16

# 看异常落在哪个模块/偏移
python tools\trace_after_stub.py "psdto3d2022绿色版" "_test\3d2_nobg.psd" 7 25

# 素材体检
python tools\psdlayers.py "psdto3d10.1绿色版\sample\3d2.psd"
```
