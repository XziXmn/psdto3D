## 4. 关键的、可直接用于重写的结论

| 结论 | 等级 | 出处 |
|---|---|---|
| 所有 DLL 导出一律 **`stdcall`**（12 个导出无例外） | A | ABI |
| 各模块导出的函数体走 `TFileStream` + `TStream.Read/WriteBuffer`，**没有 TIFF/PSD 库对象层** | A | cmyktiff2 §4.6 / PSD读写 §3.5 |
| PSD 通道 **77.5% 是 RLE 压缩**，读侧必须实现 PSD 风格 PackBits（每行 2 字节长度 + 控制字节） | A | PSD读写 §3.95 |
| 尺度以**万分比**（1/10000）保存；高度 >1500 时等比缩到 1200 | A | PSD读写 §2.1 |
| 写出 TIFF 的 Software 标签固定为 `ok3d.com email:sales@ok3d.com hongmin guo +86-755-36843399` | A | cmyktiff2 §4.8 |
| `mergtotiff` 的合并核心不在本模块，而是 `LoadLibrary("rip3d.dll")` + `GetProcAddress("stai")` | B | cmyktiff2 §2 |
| 2022 与 10.1 的命名函数清单**逐项一致**（4,640 个，零差异） | A | 版本差异 §4.2 |
| `.tw3d2` 为 GBK + CRLF，魔数 `99100`，曲线坐标行带额外 CR | A | tw3d2 §机械验证 |

## 5. 证据等级怎么读

| 等级 | 含义 | 能不能作为补丁依据 |
|---|---|---|
| **A** | 直接从二进制/真实产物读出，可逐字节复核 | 可以 |
| **B** | 工具解析 + 至少一次交叉验证 | 可以，注明验证方式 |
| **C** | 单一路径推断，未交叉验证 | **不可以**，需先补证 |
| **D** | 猜测 | **绝对不可以** |

详细定义见 `docs/逆向_整体原理.md`。

**本文档里所有 C 级结论都汇总在 `反编译_验收.md` 的「未决问题」表里**，共 4 条。

## 8. 已知边界（务必先看）

1. **阶段 B 的「CODE 覆盖率 ≥95%」已达标**：八个模块 **96.7–97.5%**。
   关键在于口径：`code-flow` 区里 98.6% 的字节紧接函数结束地址，是**函数尾巴**，
   先前没记进 `size` 字段，导致我一度报出 91.0–94.6% 的偏低数字。
   两种口径都披露：严格口径（只算已记录函数体）91.0–94.6%；含函数尾巴 96.7–97.5%。
   数据见 `_analysis/coverage_corrected.tsv` 的 `code_pct_fixed` 与 `code_pct_with_tail` 两列。
2. **命名覆盖率的两种算法**：排除 Ghidra 跳转桩（非原始过程）后 `psdto3d101` 为 75.5%；
   把跳转桩也算进分母则 63.1%。两种都已披露。
3. **4 条 C 级未决**（RLE 解压归属、`"3d99"` 用途、`0x9984` 分支、30 个 `_UnitNN` 命名）。
4. **`归档/实验/_export_test/` 下 4 个 PSD 的 width=0**，是坏产物，不可当格式样本。
5. **伪 3D 视差的公式已查清**（见 `反编译_原理与公式.md` §7.5，A 级）：
   本质是线性视差 `X_out = ROUND((depth_i − depth_ref) × (frame+1−phase) × strength / (frames−1) / 10000) + x_i`，
   不是真 3D——无投影矩阵、无光照。
   仍未分析的是 `rip3d.dll!stai`（TIFF 合并实现）、`cmyk.dll` 的三个导出、`ok3d.dll`(1.63 MB，0 导出)；
   `3d.dll` 实为 BMP 位图而非代码。
