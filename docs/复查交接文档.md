## 1. 任务与硬性约束（来自 LO，不可违背）

- 软件：PSDTO3D 2022（`psdto3d101.exe`，Delphi/VCL，32 位，中文柱镜光栅立体印刷制版工具）。
- 目标：**修复原软件使其完全可用，并完全去除加密狗**（像 99 版那样）。
- 交付物必须是**单独 exe**（可以带 DLL，但不能有外置脚本/程序）。
- 优先"修原软件"，不是写新软件。
- LO 的实机工作流：**导入 psd → 通过"导入设置"导入勾线文件 → 预览 → 输出 tiff → 输出 psd**。
- LO 的后置软件 LenticularOmega（github.com/XziXmn/LenticularOmega）消费本软件输出的 PSD。

## 4. 已验证的事实（附验证方法，可复现）

1. **狗是存储设备，不是密码机**。`tools/dump_dongle.py` 直接读 `\\.\PhysicalDrive1` 得到 1,049,088 字节全 0；真实数据在厂商私有 SCSI 命令后面。设备在设备管理器里就是普通 `USBKey USBKeyCo.` 磁盘，RAW、无盘符、无驱动。
2. **SCSI 协议**（由 `cmyktiff2.dll` 内的记录器捕获，60 条全记录在 `_export_test/scsi_record.txt`）：
   - 传输：`DeviceIoControl` 码 `0x0004D014`（IOCTL_SCSI_MINIPORT），80 字节缓冲
   - SCSI_PASS_THROUGH 头 0x2C 字节：`ScsiStatus`+2、`DataIn`+8、`DataTransferLength`+12、数据指针+20、CDB+28
   - CDB：`op=CDB[0]`（0xDD=写 0xD1=读）、`len=CDB[2..3]`、`addr=CDB[4..5]`
   - 一个会话约 20-60 次调用；写 N 字节后读 N+5（尾部 5 字节状态，多为 `FB 00 00 00 00`，`FB 01 00 48 01`、`FB 2D 00 00 00` 为特定应答）
   - **`*lpBytesReturned` 必须给 0x2C**，给 0 程序会放弃整个握手（实测）
3. **`.lll` 文件 = 从狗里读出的授权块本身**（不是解密缓存）。8 个：cmyk3d 194B / cmyk3d_Ini 26B / cmyktifsave 106B / opensaveset 42B / readpsdpwph 58B / rip3d 18B / savergbtif 106B / savetif0 114B。`.enc` 是磁盘上的另一份（同样加密态）。
4. **exe 静态导入 `cmyktiff2.dll`** → 它的 DllMain 在程序任何代码之前运行，是唯一可靠的注入点。
5. **反调试**（见 §2）。
6. **菜单命令号**（`tools/menu_ids.py` 从 HMENU 实读）：3=打开工程 7=导入*.psd 10=导入设置(Ctrl+Alt+I) 12=预览F9 13=停止F10 14=红蓝预览 16=输出tiff 17=输出PSD 18=输出Gif。
7. **TIFF 交错算法已复刻**：`cmykdrop/cmykdrop.c` 的 mergtotiff 重写，与带狗产出逐像素一致（`tools/compare_tiff.py`，平均差 0.000000）。注意：这验证发生在"视图文件已由带狗会话生成"的前提下。
8. **PSD 输出格式已量死**（两个实机样本）：8BPS；CMYK 变体=13 层 ghm01..13 每层 5 通道(-1,0,1,2,3) 无压缩 1575×1890；RGB 变体=11 层 ghm01..11 每层 4 通道 4370×5197。合成图在层段之后。
9. **99 版是去过狗的同一套软件**（以 `docs/任务.md` 为准，本条旧结论作废）。目录 `psdto3d99绿色版\psdto3d99绿色版\`：无 `.enc` / `.lll` / `my32.dll`，TIFF 模块是 `cmyktiffd.dll`（无狗字符串），导出参数写成常量。`exe3d.dll` 与 `cmyktiffd.dll` 仅差 4 字节（0xBD44/0x63796 处 `20 41`→`00 01`），exe 有非 Borland 的 `.Geddon` 导入节。视图、视差、交错与 2022 同一原理。2022 去狗照这个结果做：补丁 exe，或劫持它加载的 DLL。
10. **my32.dll（162 导出的厂商 SDK）主流程从不加载**（转发代理实测 0 次调用）。

## 5. 去狗仿真器现状

代码：`cmykdrop/dongle_fake.c`（主逻辑）、`dongle_mem.h`（从 scsi_record.txt 生成的槽位应答表）、`iatpatch.c`（IAT 扫描线程 + VEH + 函数钩子）、`dlgstub.c`（对话框接管）。构建：

```
/tmp/winlibs32/mingw32/bin/gcc -shared -O2 -o cmyktiff2_fake.dll \
  cmykdrop.c dongle_fake.c iatpatch.c dlgstub.c -static -static-libgcc -Wl,--kill-at
```

原理：exe 的 IAT 里 hook `SetupDiGetClassDevsA/EnumDeviceInterfaces/GetDeviceInterfaceDetailA/DestroyDeviceInfoList`（伪造一个 `\\?\usbstor#disk&ven_usbkey&...` 磁盘接口）+ `CreateFileA`（把该路径换成本地文件句柄）+ `DeviceIoControl`（用 `dongle_mem.h` 查表应答）。

曾经的结果（**已被污染，见 §7.6，需重测**）：无狗时 8 个 `.lll` 全部重建且 md5 与带狗一致。

当前默认行为（**安全**）：不伪造设备（需 `FAKE_DEV=1` 才启用）、不写内存（`DO_CLEAR` 默认关）、无 `_dlgopen.txt` 时对话框走真的。

环境开关：`NODLGPATCH=1`（让 Python 启动器不盖 DLL 的对话框钩子，**跑测试必须加**）、`FAKE_DEV=1`、`DO_CLEAR=1`（**危险**，见 §7.6）、`GARBAGE_DEV`/`DENY_DEV`（诊断用）。
