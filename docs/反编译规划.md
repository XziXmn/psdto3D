# PSDTO3D 反编译规划

> 建立：2026-11-22
> 依据：`_analysis/pe_inventory.json`（2026-11-22 全量体检）、`_work/re_all`、`_work/re_keyreg`、`_analysis/dump_cmyktiff2`（2026-11-22 试点）
> 定位：给「去狗」和「按原理重写」提供可核对、可复现的代码底图。**不是**产出可直接编译的 Delphi 工程。

---

## 0. 一句话结论

三套程序的核心模块全部是**未加壳的 PE32 / Delphi 7**，没有 .NET、没有 VMProtect/Themida、没有反调试、没有 PDB，导出表、DFM 窗体、RTTI 类名、published 事件名都在。**代码层可以全量反编译。**

但仓库现有的"全量反编译"只等于「Ghidra 认出来的函数 100%」，不等于「代码 100%」：主程序函数体只覆盖 CODE 段的 **58.4%**，cmyktiff2.dll 试点覆盖 **67.1%**。缺口不是数据，是 Delphi 单元初始化块、SEH 桩和只被 VMT 间接调用的方法——需要一轮 Delphi 专用函数发现才能补上。

---

## 1. 目标与非目标

### 1.1 目标（可验收）

1. 每个 P0/P1 模块产出：**全函数伪代码 + 地址→名字映射 + 调用图 + 导出 ABI 说明**。
2. 主程序：菜单命令 → 处理函数地址的完整映射；授权闸门、工程解析、渲染/导出调用链可逐行核对。
3. `cmyktiff2.dll`：7 个导出函数的参数、返回、调用约定、关键分支全部落到文档。
4. 99 / 10.1 / 2022 三版本可 diff：授权差异、TIFF 常量差异、工程解析差异各有对照表。
5. 所有结论标注证据等级（A/B/C/D，沿用 `docs/逆向_整体原理.md` 的约定），可复现：脚本 + 输入哈希 + 输出目录。

### 1.2 非目标

| 不做 | 原因 |
|---|---|
| 重建可编译的 Pascal 工程 | VCL 静态链接，私有方法名/局部变量/类型已丢；收益远低于人工重写 |
| 反编译 `my32.dll` | 第三方 USBKey SDK（MSVC 6.0，162 个导出），仿真/桩比读代码便宜 |
| 反编译 Blender、Windows USB 驱动 | 与目标软件无关 |
| 把 `.enc` 解密当反编译任务 | 那是数据加密 + 狗协议，已有独立成果；反编译只负责看清调用点 |
| 给 Borland/VCL 库函数逐个命名 | 噪声大、无业务价值；用签名库批量标记即可 |

> 旧文档写"4816 个函数"，实际是 4,814 个内部函数 + 513 个导入，后面引用统一按本表。

### 3.2 覆盖率（按函数体字节 / CODE 段原始大小）

| 模块 | 函数体合计 | CODE 段（原始大小） | 覆盖率 | 未覆盖 |
|---|---:|---:|---:|---:|
| 2022 主程序 | 658,208 B | 1,127,424 B | **58.4%** | 469,216 B |
| cmyktiff2.dll | 358,159 B | 534,016 B | **67.1%** | 175,857 B |

### 3.3 缺口里是什么（抽样证据）

对主程序 7 个最大缺口各反汇编 40 字节，全部是有效代码，不是数据填充：

| 缺口 | 大小 | 样本特征 |
|---|---:|---|
| `0x44cb6e–0x4529f4` | 24,198 B | `55 8B EC 33 C0 55 68 … 64 FF 30`，Delphi 单元初始化 + SEH 帧 |
| `0x43d570–0x4421e8` | 19,576 B | `E9 … EB … 5F 5E 5B 8B E5 5D C3`，错误/收尾桩与短方法 |
| `0x4d31b6–0x4d5e78` | 11,458 B | `ret 0x54` 结尾，参数清栈的方法 |
| `0x474865–0x4770f8` | 10,387 B | 同上，方法尾部 + 对齐填充 |
| `0x507dd5–0x509e44` | 8,303 B | 单元收尾 + `mov ecx,5 / push 0` 的初始化模板 |

结论：缺口主要是三类——
1. **Delphi 单元 init/finalization 表**里的函数，只被数据表引用，没有直接 `call`；
2. **只被 VMT 间接调用**的虚方法/事件处理；
3. **SEH 处理器与编译器桩**（`push <handler>` + `fs:[0]` 链）。

### 3.4 现有语料的三个缺陷

1. **地址即文件名，没有名字**。业务函数仍是 `FUN_004d91a4`，读起来靠猜。
2. **没有按模块的 manifest**。函数数、覆盖区间、失败数散在 journal 里。
3. **VCL 噪声大**。exe 静态链接了整个 VCL，4,814 个内部分函数里有相当比例是 Borland 库，不标出来会淹没业务代码。

## 6. 实施阶段

### 阶段 A — 基线固化（0.5 天）

| 任务 | 内容 | 产物 |
|---|---|---|
| A1 | 对全部 P0/P1 模块记录 SHA-256、代码段大小、导出数、DFM 数、PACKAGEINFO 单元名 | `_analysis/baseline.json` |
| A2 | 校验 `re_all` / `re_keyreg` 的函数数、地址范围、失败数，写入 manifest | `_analysis/baseline.json` |
| A3 | 固定 Ghidra 版本、脚本版本、Java 版本 | 同文件 `environment` 段 |

**验收**：任一模块能从 `baseline.json` 查到「源路径 → 哈希 → 语料目录 → 覆盖率」，三项缺一不可。

---

### 阶段 B — 函数发现补齐（1–2 天）

目标：把 P0 模块的 CODE 覆盖率从 58–67% 提到 **≥95%**，且不把数据误判成代码。

| 子任务 | 做法 | 验证 |
|---|---|---|
| B1 单元 init/final | 从 `System.@StartExe` / `@Halt0` 的立即数定位 InitTable/ExitTable；按表项批量 `createFunction`；兜底用 Delphi 7 初始化模板 `55 8B EC 33 C0 55 68` 扫描 | 抽样 20 个新函数，确认有 `inc dword [全局]` 初始化语义 |
| B2 VMT / 方法表 | 扫 DATA：`dword[vmt-76] == vmt` 且 `dword[vmt-44]` 指向短字符串类名 → 判 VMT；按 `vmtMethodTable`（-52）解析 `TMethodTable`（size/address/name），把 published 方法与事件名直接映射到地址 | 与 DFM 里的事件名交叉核对，命中率 ≥90% |
| B3 SEH 桩 | 扫 `push <handler>` + `64 FF 30`（`fs:[0]`）模式，把 handler 地址建函数 | 每个 handler 能被反编译，无重叠冲突 |
| B4 重跑与报告 | 对 P0/P1 重跑 `DumpAll.java`，生成 `coverage.tsv`（模块/函数数/字节/覆盖率/失败数） | 覆盖率 ≥95%，失败数 = 0 |

**产物**：`_analysis/ghidra_scripts/DelphiInit.java`、`DelphiVMT.java`、`DelphiSEH.java`；各模块 `dump_<module>/` 更新。

**闸门**：B3 之后先人工抽查 20 个新函数；若误判率 >5%，回退并只保留 B1/B2。

## 7. 目录与命名约定

```
_analysis/
  baseline.json                # 哈希/尺寸/覆盖率/环境
  pe_inventory.json            # 全量 PE 体检
  coverage.tsv                 # 阶段 B 后的覆盖率总表
  ghidra_scripts/
    DumpAll.java
    DelphiInit.java
    DelphiVMT.java
    DelphiSEH.java
  dump_<module>/               # index.tsv + 0xADDR.c
  names/<module>.json          # 地址 → 名字/类/签名
  dfm/<module>/*.dfm
  logs/<module>_<date>.log
docs/
  反编译规划.md                # 本文件
  反编译_ABI.md
  反编译_<module>.md
```

规则：

1. **按 SHA-256 建目录**，不按文件名。三套安装里同名 DLL 的哈希不同，混用会得出错误结论。
2. 原目录只读；所有产物写 `_analysis/`。
3. 覆盖/结论必须能追溯到「模块哈希 + 函数地址 + 证据等级」。
4. 证据等级沿用：A = 二进制 + 运行时双确认；B = 静态可见；C = 推导自洽；D = 假设，**不得据此打补丁**。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Ghidra 对 Delphi `register` 约定产生 `extraout_EDX/ECX` | 伪代码可读性差，参数归属易错 | 用 IDR 签名修正；精读时以调用点压栈顺序为准；不凭伪代码猜参数 |
| 超大函数（`mergtotiff` 14.8 KB） | 一次读不完，容易迷失 | 按基本块/字符串引用切片；配合断点日志；先画数据流再读 |
| 函数发现误判（把数据当代码） | 覆盖率虚高，结论污染 | 新函数必须抽样验证；B3 设 5% 误判回退闸门 |
| 三版本同名文件混淆 | 把 99 的结论套到 2022 | 全部按 SHA-256 归档；文档引用必须带哈希前缀 |
| VCL 噪声淹没业务代码 | 命名工作量爆炸 | 只给业务单元命名；Borland 库用签名库批量标记，不逐个读 |
| 反编译变成时间黑洞，拖住去狗 | 第 1 段验收延期 | 阶段 B/C 只做 P0；D 按需；去狗验收标准仍以 `docs/任务.md` 为准 |
