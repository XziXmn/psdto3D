## 2. `readpsd`（`0x4B9528`，701 行）

### 2.1 结构概览（B 级）

- 签名 `void readpsd(void)` —— 参数走 Borland 寄存器约定，Ghidra 未还原。
- 被调最多：`FUN_0041c65c` **37 次**、`FUN_004b9508` **12 次**、`FUN_00402a84` 11 次、
  `FUN_00429d9c` 8 次、`FUN_00428dec` 8 次。
- 字符串常量只有一处：`"\x11\x02.\x04"`（成对出现的标记字节，像类型标签）。

### 2.2 两个关键被调函数（A 级，函数体全文可见）

**`FUN_004b9508` = 32 位字节序交换**

```c
uint FUN_004b9508(uint param_1)
{
  return param_1 >> 0x18 | (param_1 & 0xff0000) >> 8
       | (param_1 & 0xff00) << 8 | param_1 << 0x18;
}
```

**这条极具说明力**：PSD 文件格式是大端，x86 是小端，所以读写 PSD 的整数必须翻转。
`readpsd` 调 12 次、`writepsd` 调 22 次，正好对应各自的字段解析/写回密度。

**`FUN_0041c65c` = 带错误检查的流读取封装**

```c
void FUN_0041c65c(int *param_1, undefined4 param_2, int param_3)
{
  if (param_3 != 0) {
    iVar1 = (**(code **)(*param_1 + 0xc))(param_1, param_2, param_3);   // 虚表 +0x0C
    if (param_3 != iVar1) { … 构造异常对象 … }                          // 短读即抛
  }
}
```

即「读 `param_3` 字节，读不满就抛异常」。`writepsd` 侧的对应物是 `FUN_0041c694`（虚表 +0x10）。

## 3. `writepsd`（`0x4BAA64`，585 行）

### 3.1 结构概览（B 级）

- 被调最多：`FUN_004b9508`（字节序）**22 次**、`FUN_0041c694`（写封装）13 次、
  `FUN_0040279c` 9 次、`FUN_00404140` 8 次。
- **字符串常量：`"vwd1.gjs"`、`"vwdt1.gjs"`**。

### 3.2 与既有结论的交叉验证（B 级）

`docs/自动化测试与导入现状.md` 记录过：程序会在 `C:\ok3dtemp\` 下写出
`lyt1.gjs … lyt12.gjs` 共 12 个每层数据文件。本轮在 `writepsd` 里直接读到
`vwd1.gjs` / `vwdt1.gjs` 两个字面量，**证明 `.gjs` 的写出发生在本 DLL 内**，
不是主程序行为。

> 这点对重写很关键：`.gjs` 不是中间残留物，而是 `writepsd` 的正常产物。

## 4. 与主程序的关系　【已查清，并推翻本文早期推断】

**2022 主程序不使用 `8602.dll`。** 全语料检索 `8602` 零命中。

主程序实际动态加载的是 **`zu06.dll`**，全部调用点已定位（B 级，逐行可见）：

### 4.1 `readpsd`：启动时绑定并调用（`FUN_005043F0`，3,773 B）

```

行 213   DAT_00523274 = GetProcAddress(DAT_00523268, "readpsd")
行 238   WVar4 = (*DAT_00523274)();
```

### 4.2 `writepsd`：在「导出 PSD」里绑定（`TForm1_PSD1Click`，`0x50B090`，58 行）

```
行 38    _DAT_0052326c = LoadLibrary("zu06.dll")
行 40    _DAT_00523278 = GetProcAddress(_DAT_0052326c, "writepsd")
行 42    WVar2 = (*_DAT_00523278)();
```

`"zu06.dll"` 与 `"writepsd"` 在 `0x0050B1F4` 处是**内联的以 0 结尾字符串**
（`7a 75 30 36 2e 64 6c 6c 00 ... 77 72 69 74 65 70 73 64 00`），不是普通字符串常量。

### 4.3 结论

| 结论 | 等级 |
|---|---|
| `8602.dll` 导出 `readpsd`/`writepsd`，实现含字节序转换与短读异常 | A/B |
| **2022 主程序不引用 `8602.dll`** | **B（全语料零命中）** |
| 主程序真正使用的是 `zu06.dll`，两个入口均在运行时 `LoadLibrary`+`GetProcAddress` | **B** |
| `8602.dll` 应视为同族的另一版本，而非 2022 的运行时依赖 | B |

> 这一点对规划有影响：P0 模块清单里列的 `8602.dll`，实际运行时并不被加载。
> 真正该纳入 P0 的是 **`zu06.dll`**（已补语料到 `_analysis/dump_zu06_b/`）。
