### 1.1 是同一族的证据（B 级）

- **导出完全一致**：五个都是 `readpsd` + `writepsd` 两个入口，无其它导出；
- **单元集合高度重合**：`zu06/zu6/zu61/dspr` 各 32 个业务单元，
  与 `8602` 的 53 个相比交集 31～32 个；
- **每个变体带自己的单元名**：`zu06` 有 `zu06`、`zu61` 有 `zu61`、`dspr` 有 `mdspr`
  （`zu6` 无额外单元，说明它的名字就在交集里）。

### 1.2 代码段字节相似度（A 级，同长度部分逐字节比对）

|  | zu06 | zu6 | zu61 | dspr | 8602 |
|---|---:|---:|---:|---:|---:|
| **zu06** | — | 93.3% | 93.3% | 3.7% | 3.0% |
| **zu6** | | — | **98.4%** | 3.7% | 3.0% |
| **zu61** | | | — | 3.8% | 3.0% |
| **dspr** | | | | — | 3.0% |

**分簇（B 级）**：

- **近同簇**：`zu6` ≈ `zu61`（98.4%），`zu06` 与二者 93.3% —— 同一支的三次编译；
- **独立簇**：`dspr`（与上面三个只有 ~3.7%）、`8602`（与所有都 ~3.0%）。

> 3% 这个量级并不等于「无关」：这些镜像的 CODE 段里混有大量 RTTI/常量表，
> 加上整体地址平移，逐字节比对会被放大。**判断族属应以「导出 + 单元集合」为准**，
> 字节相似度只用于分支内排序。

### 1.2b `zu06` 与 `8602` 的两个导出对照（B 级，两侧均有语料）

### 1.2c 修正：字节相似度把 `dspr` 判错了（第 49 轮，符号级复核）

第 1.2 节按「同长度前缀逐字节比对」得出：`dspr` 与 `zu6`/`zu61`/`zu06` 只有 **~3.7%** 相似，
判为「独立簇」。**这个判断是错的。**

对五个模块各做一次 IDR 分析（每个都恢复出 67 个单元、约 3,850 条名表），
按「单元 + 函数名」比集合：

| | zu6 | zu61 | zu06 | 8602 | dspr |
|---|---|---|---|---|---|
| 命名函数数 | 2,479 | 2,479 | 2,479 | **3,119** | 2,467 |
| zu6 | — | **1.000** | **1.000** | 0.785 | **0.995** |
| zu61 | | — | **1.000** | 0.785 | **0.995** |
| zu06 | | | — | 0.785 | **0.995** |
| 8602 | | | | — | 0.786 |
| dspr | | | | | — |

**符号级看：`zu6` = `zu61` = `zu06`（完全相同），`dspr` 是 0.995，几乎一样。
真正的外点是 `8602`（0.785）。**

### 为什么字节法会把 `dspr` 判错

比对各单元初始化地址：

| | zu6 vs zu61 | zu6 vs dspr |
|---|---|---|
| 共有单元名 | 66 | 66 |
| **地址完全相同的** | **66 / 66** | **1 / 66** |
| `_Unit1` 地址差 | 0 | **−1,784 B** |
| `sysutils` 地址差 | 0 | −1,792 B |
| `_Unit8` 地址差 | 0 | −1,908 B |

`dspr` 的单元名与 `zu6` 一模一样，但**所有地址整体前移约 1.8 KB**——
它是**同一份源码用不同链接布局编译出来的**。

在「固定偏移逐字节比对」下，整体平移会让所有字节都对不上，于是得出 3.7% 的荒谬数字。
**字节相似度只对「几乎同一构建」有意义，一旦布局变动就失效。**

### 修正后的族内关系

| 关系 | 证据 |
|---|---|
| `zu6` ≡ `zu61` | 66/66 单元地址相同 + 符号集合 Jaccard 1.000 |
| `zu6` ≡ `zu61` ≡ `zu06` | 符号集合 Jaccard 全部 1.000 |
| `dspr` ≈ 上述三者 | Jaccard 0.995；单元名相同但地址整体平移 ~1.8 KB（另一布局的构建） |
| `8602` 独立 | Jaccard 0.785；命名函数 3,119 个，比同族多约 640 个；另带 `TREG` 窗体 |

**证据等级：A**（单元地址来自 IDR 的单元表；符号集合来自 IDR 名表；两者都可复核）

> 教训与第 44 轮同源：**单一的相似度指标不能当结论**。字节法在布局平移时会失效，
> 必须用与布局无关的口径（符号集合、单元名）来交叉验证。

### 1.3 `8602.dll` 的窗体（A 级，值得注意）

`8602.dll` 内嵌 **6 个** DFM：`TABOUTBOX`、`TFORM1`、`TFORM2`、`TLOGINDIALOG`、
`TPASSWORDDIALOG`、**`TREG`**。

其中 `TREG` 是 **99 时代**的注册窗体（见 `docs/反编译_版本差异.md` 第 2 节：
2022 用 `TREGFORM`，99 用 `TREG`）。也就是说这个库把旧版窗体集一并编译进去了，
运行时未必用得到——重写时不要把它当成 2022 的界面依据。

|---|---|---|

## 5. 复现

```bash
# 导出与内嵌窗体（A 级数据）
python - <<'PY'
import pefile
from pathlib import Path
for rel in ('Psdto3d/8602.dll','Psdto3d/zu6.dll','Psdto3d/3d99.dll','Psdto3d/G3d99.exe'):
    pe = pefile.PE(rel, fast_load=True)
    pe.parse_data_directories(directories=[
        pefile.DIRECTORY_ENTRY['IMAGE_DIRECTORY_ENTRY_EXPORT'],
        pefile.DIRECTORY_ENTRY['IMAGE_DIRECTORY_ENTRY_RESOURCE']])
    ex = [s.name.decode() for s in getattr(pe.DIRECTORY_ENTRY_EXPORT, 'symbols', []) or []]
    dfm = []
    for rt in pe.DIRECTORY_ENTRY_RESOURCE.entries:
        if rt.id != pefile.RESOURCE_TYPE['RT_RCDATA']: continue
        for e in rt.directory.entries:
            nm = e.name.string.decode('latin-1') if e.name else str(e.id)
            for l in e.directory.entries:
                d = l.data.struct
                if pe.get_data(d.OffsetToData, 4) == b'TPF0': dfm.append(nm)
    print(Path(rel).name, ex, dfm)
PY

# 单元集合
python -I _analysis/pkg_info.py Psdto3d/zu6.dll
```
