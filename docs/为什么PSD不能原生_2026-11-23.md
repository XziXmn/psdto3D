# 为什么 PSD 不能原生写出 · 还差什么（2026-11-23 16:1x）

## 一、原生路径的完整调用链（已从反编译+反汇编确认）

```
菜单 17  →  PSD1Click
    └─ call [0x523278] = zu06.dll!writepsd
         参数: (文件名, 临时目录, 3000000, 0, 252000, 0, 层数=11, 宽=4370, 高=5197, 3)
         │
         ├─ 写 PSD 头 + 11 条层记录        ← 这部分它写对了（我们已验证与真机基准逐字段一致）
         │
         ├─ FUN_00486FBC(...)              ← 拼出配置路径与 11 组参数串
         │     └─ FUN_00497670(配置路径, ..., &位图A, &位图B)
         │           ├─ FUN_004942D8       读 cmyk3d.enc.lll（纯读文件，不解密）
         │           └─ FUN_004963C8(缓冲, 长度, ..., &位图A, &位图B)   ★ 真正干活的地方
         │                 └─ 返回 0 才算成功；调用方只在 0 / -43 / -67 时继续
         │
         └─ 层循环（11 次）
               for row in 1..位图A高度:
                   for col in 1..位图A宽度:   ← 位图是 0×0，所以一个字节都不写
```

**exact 证据**：
* 层循环守卫在 `zu06+0xA4965`：`mov eax,[ebp+0x20]; test eax,eax; jle 0x4a51ca`，
  `[ebp+0x20]` = 层数 = 11 → 守卫通过，循环进入；
* 循环里两次 `call 0x4223A8`（= `TBitmap.ScanLine`，已确认读取 `+0x20`=高度、`+0x2c`=基址）；
* 循环边界来自这两个 `TBitmap`，它们为 0×0 → 内层 `if (0 < 列数)` 不成立 → 跳过所有写入；
* 结果：文件里只有头 + 层记录 = **3,080 字节**（正是我们看到的）。

## 三、所以"还差什么"——只差一件东西

**`FUN_004963C8` 的成功条件。**

它只有 123 行，输入是：
* 194 字节的 `cmyk3d.enc.lll`；
* 11 组参数字符串（由 `FUN_00486FBC` 从 writepsd 参数拼出）；
* 输出：两个 `TBitmap`。

现在的行为是"返回非 0 → 位图不生成"，我们只需搞清楚它**判失败的那几行**：
* 如果失败是"配置里的校验字段与机器/狗绑定"→ 可伪造一份能通过的配置（**无需狗，原生写出**）；
* 如果失败是"缺某个运行时句柄"→ 在 DLL 层补给它。

**工作量估计**：读 123 行 + 上游 92 行，2~3 小时能给出结论并试着让原生写出成立。
