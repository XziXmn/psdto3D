# 实机采集：狗通道的完整 SPT 包头

目标：拿到程序自己发出的**完整 44 字节 SCSI_PASS_THROUGH 包头**。
现在只剩这一份数据没到手；有了它，探针就能逐字节复现，不会再写挂设备。

---

## 0. 先确认设备在宿主机上健康

宿主机（管理员 PowerShell）：

```powershell
Get-PnpDevice -InstanceId 'USB\VID_1312&PID_2012\6&2BCCCFA4&0&1' | Format-List Status,Problem
Get-Disk | Where-Object BusType -eq 'USB' | Select-Object Number,FriendlyName,Size
```

期望：`Status=OK`、`Problem=CM_PROB_NONE`，并且能看到 `USBKey USBKeyCo.,`（1,049,088）。

设备卡死时（`Problem=10` 或 `CM_PROB_WILL_BE_REMOVED`）用这套复位：

```powershell
usbipd unbind --busid <当前 busid>
pnputil /remove-device "USB\VID_1312&PID_2012\6&2BCCCFA4&0&1"
Start-Sleep 3
pnputil /scan-devices
Start-Sleep 3
usbipd bind --busid <新的 busid> --force
usbipd list
```

## 1. 采包（只跑程序，不跑探针）

目录：`_work\real3\`（已就绪）

| 文件 | 说明 |
|---|---|
| `psdto3d101.exe` | 原版，md5 `5407b481…`，未改动 |
| `cmyktiff2.dll` | **抓包版**，只记录并转发，不改变行为 |
| `cmyktiff2_orig.dll` | 厂商原版，转发目标 |
| `_dlgopen.txt` | 对话框自动应答：`C:\bio\a.psd`、`C:\bio\a.tw3d2` |

把整个 `_work\real3\` 拷到**设备所插的那台机器**上（不必是虚拟机），双击 `psdto3d101.exe`，然后：

1. 菜单 7 → 导入 PSD（对话框会自动填 `C:\bio\a.psd`）；
2. 菜单 10 → 导入工程（自动填 `C:\bio\a.tw3d2`）；
3. 等几秒，关掉程序。

产出：同目录下 `_dongle.log`，里面有每个请求的完整包头，形如：

```
SPT 2C00000000000000 00000000 100000000A000000  ← 前 20 字节
SPT 0000000000000000 00000000000000000000      ← 后 24 字节（含 CDB[0..15]）
LOG 写 addr=0000 len=496 dtl=496 data=…
LOG 读 addr=0000 dtl=5 ret=44 data=…
```

把 `_dongle.log` 发回来即可。

## 2. 可选：本地探针复现

同机放 `dongle_probe.exe` + `block496.bin`，管理员运行：

```powershell
.\dongle_probe.exe C:\out                     # 只读，READ CAPACITY
.\dongle_probe.exe C:\out --cdbw <从日志抄来的 32 位 hex> --cdbr <同上> --write --limit 1
```

`--cdbw` / `--cdbr` 是写/读两个方向的 CDB 覆盖，直接照抄日志里的 16 字节即可。
任何一步失败会立即退出，不会连着打。

---

## 3. 判读

拿到 `_dongle.log` 后要回答的两个问题：

1. 程序写的 CDB 里，`CDB[1]`、`CDB[6..15]` 是否非零？——这决定探针之前为什么会把设备写挂；
2. 读的 CDB 是否与写不同（不只在 `[0]` 上）？

拿到这两点，用户态 DLL 就能按真实包构造应答，不必再碰设备。
