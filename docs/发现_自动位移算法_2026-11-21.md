## 二、0x502CA8 的算法（已逐指令核对）

```
E = 32 层里「记录+0x2C 字节 == 0」的层数              （0x504C94 循环）
F = ROUND( 2×(E−1) / 5.0 )                            （0x504D08，常量 0x505424=5.0）
base = ROUND( 宽 / 16.0 × 10000 )                     （0x504BBA，常量 16.0/10000.0）
step1 = ROUND( base×2/3 / (0.001 + F) )               （0x502CA8 内，c74≈0.001）
step2 = ROUND( base / ((E−F) − 0.999) )               （c80≈0.999）

for i = 0..F      : VALS[map[i]] = ROUND(step1 × (i−F))
for i = F+1..E−1  : VALS[map[i]] = ROUND(step2 × (i−F))

表格 col2 第 r 行 = ROUND( VALS[32−r] / 10000 )      （0x502CA8 尾部循环）
```

- `map` 是收集层序号（从 N−1 递减）的数组，`0x5231F8`；`VALS` 是 int64 数组，`0x5231F4`。
- 实测（v13，导入 a.psd）：E=10、F=4、base=2731250、step1=455095、step2=546141。
- 实测（v14，补丁后）：E=32、F=12、step1=151723、step2=143742。

## 九、v15：群组列修复（0x2C 清零 cave）

问题：导入 PSD 后，层记录 `+0x2C` 字节有 22 个非零值 → 群组列显示 A/B/D/E…（真狗全空）；
同时它让 E 只数到 10 → F=4 → 移位全错。

修复点：`0x504C72`（`0x5043F0` 里 E 统计之前，原指令 `mov byte [0x5230C7],0`）。
打法：该 7 字节替换为 `E9 rel32 90 90`，跳到 cave `0x4E0A00`：

```
C6 05 C7 30 52 00 00     原指令 mov byte [0x5230C7],0
50 51 52                 push eax/ecx/edx
8B 15 B4 30 52 00        mov edx,[0x5230B4]
B9 20 00 00 00           mov ecx,32
C6 42 2C 00              loop: mov byte [edx+0x2C],0
83 C2 38                 add edx,0x38
49                       dec ecx
75 F6                    jnz loop
5A 59 58                 pop edx/ecx/eax
E9 52 42 02 00           jmp 0x504C79
```

共 39 字节。清零发生在 E 统计之前 → E 自然=32、F=12，
v14 的 `0x504CA6: 75 33→90 90` 拐杖不再需要。

v15 实测导入 a.psd：

```

E=32 F=12 base=2731250 step1=151723 step2=143742
col1 32 行全空
col2 = -182 … 273（与真狗三张截图逐位一致）
```

产物：`_work\v15\psdto3d101.exe`（= v13 + 39 字节 cave，无 90 90 补丁）。

另注：导入后再「保存工程」会 AV（`004051C7`, Read of address 00000000），

## 十二、KeyReg101 分析结论(2026-11-21 深夜)

KeyReg101.exe(厂商注册工具,619KB)全量反编译完成(2708 函数,_work/re_keyreg/)。

结论:KeyReg101 与主程序是**同构的验证工具**,不是授权生成器:
- 0x4607A4 = LoadLibrary(wnaspi32.dll) + GetASPI32SupportInfo/SendASPI32Command(同 exe 0x4D2208)
- 0x460878 = ASPI 会话(SRB Cmd=2, 36 字节标识 memcmp DAT_0047DFA4)
- 0x46093C/0x4609E8 = SPT 写/读(CDB 由调用者构造,DD FE 协议同 exe)
- 0x460B18 = .enc 处理(8 槽 + 7B×4 验证 + 257 次循环,同 exe 0x4D2F14/0x4D2ADC)
- 标识模板 DAT_0047DFA4 与 exe 的 DAT_00517C5C **逐字节相同**(36B: USBkey/USBkeyCo./1.00)

即:KeyReg101 也是「发命令 → 比对狗应答」的验证端,**没有 .enc 的加密/生成逻辑**。
授权数据的生成在厂商开发机,分发形态即 .enc 密文,密钥在狗固件 VM 应答中。

最终结论:0x4E1B1C 状态机的应答数据(含 VM 字节码)= 狗固件在会话中生成,
exe 与 KeyReg101 都只有「发送 + 比对 + 解释执行」的代码。无真狗交互记录,
应答数据在原理上不可从静态分析获得。数据级回放(cap 日志)是唯一完整路径。
