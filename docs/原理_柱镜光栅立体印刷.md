## 1. 这是什么图：柱镜光栅立体画

成品是一张**柱镜光栅板**（lenticular sheet）印刷品。板背面是印刷图案，
正面是一排排平行的半圆柱透镜（柱镜 / lenticule）。

```
       观察者眼睛（左/右）
              ↓  ↓
   ╭──╮╭──╮╭──╮╭──╮╭──╮        ← 柱镜面（正面）
   │  ││  ││  ││  ││  │
   └──┴┴──┴┴──┴┴──┴┴──┘
   |A |B |A |B |A |B |A |        ← 印刷图案（背面）
     ↑ 每个柱镜下方压着 N 条像素列
```

**光学原理**：每个柱镜只让观察者看到它正下方**某一条**像素列。
左眼看到 A 列、右眼看到 B 列（因为眼睛位置不同 → 视线角度不同 → 落点不同）。
只要 A、B 两列是同一场景的**两个不同视角**，大脑就合成立体。

所以**柱镜板把"空间上的视差"换成了"角度上的分离"**——这就是全部原理。

由此推出所有约束：

* 视图数 N 决定"有几个视角"，N 越大越顺滑（也越细，打印机要够精度）
* 每个柱镜下方必须**恰好排满 N 条列**，否则串扰（左眼看到右眼的内容 → 重影）
* 视差**只能是水平方向**——柱镜是竖直的，垂直方向没有角度分离
  **【实测确认】**：13 个视图间 `dy ≈ 0.00`，`dx` 才是视差

## 2. 三个关键参数与它们的关系

| 参数 | 含义 | 本工程实测值 |
|---|---|---|
| **LPI** | 每英寸柱镜数（材料规格，都是整数如 20/24/40/60/75/100） | **24** |
| **DPI** | 打印机输出分辨率 | **600**（输出设置里的"输出 DPI"） |
| **N（Angles）** | 视图数 | **13** |

**核心关系 —— 每个柱镜宽度占多少像素**：

```
P = DPI / LPI        （像素/柱镜，通常是小数）
本工程：P = 600 / 24 = 25.0 px
```

**每视图分到多少像素**：

```
每个视图列宽 = P / N = 25 / 13 ≈ 1.923 px      ← 小数！
```

这一条是整套技术的关键，也是所有麻烦的来源：

> **P/N 几乎永远不是整数。** 意味着"每个视图占几条列"必须**变宽**：
> 有的视图占 2 列、有的占 1 列，通过误差扩散（error diffusion）把它摊平，
> 否则累计误差会让柱镜和像素列错位，几十厘米后画面就花了。

这就是为什么 `LenticularOmega` 里 `lenticular_widths` 是个**列表**而不是单值：

```python
# LenticularOmega/rasterization.py
def compute_indices(img_idx, output_width, lenticular_widths):
    lenticular_width = sum(lenticular_widths)        # 一个柱镜的总像素宽
    lenticular_count = int(np.ceil(output_width / lenticular_width))
    image_offset_px  = sum(lenticular_widths[:img_idx])   # 本视图在柱镜内的起点
    image_lent_width = lenticular_widths[img_idx]         # 本视图分到几条列
    for group_idx in range(lenticular_count):
        pos = group_idx * lenticular_width + image_offset_px
        for i in range(image_lent_width):
            col_indices.append(pos + i)
```

当 `lenticular_widths = [1]*N` 时退化成最简单的情形：
**输出第 c 列属于第 `c mod N` 个视图**（前提是 DPI/LPI 恰好等于 N）。

标准写法（连续映射，不需要变宽表）：

```
对输出列 x（0-based）：
    t     = (x + 0.5) / P            # 落在第几个柱镜内（0..1）
    u     = t - floor(t)             # 柱镜内相对位置
    view  = min(N-1, floor(u * N))   # 该位置显示哪个视图
```

## 3. 视图是怎么来的：从分层 PSD 到 N 个视角

光栅只能"分角度"，**视差内容必须事先做好**。PSDTO3D 的价值就在这里：
它把一张**分层 PSD**（每层一个深度）自动生成 N 个视角的视图。

### 3.1 分层深度模型

工程文件里每层有两个量：

```
第 9+N … 8+2N 行：  <angle> <group>  <scale>     ← 每层一行
```

而 `立体设置` 面板上有 4 个参数（本工程实测）：`LPI=24`、`Angles=13`、`X=1`、`Depth=1`。

### 3.2 视差公式（关键）

第 j 层、第 k 个视图（k = 0..N-1）的水平位移：

```
dx(j,k) = depth_j * W * (k - (N-1)/2) / (N-1)
```

* `depth_j` —— 该层的景深系数（层自己的参数）
* `W` —— **总视差跨度**（整幅图从第一个视图到最后一个视图的最大位移，单位 px）
* `(k-(N-1)/2)/(N-1)` —— 把 k 归一化到 [-0.5, +0.5]

### 3.3 实测标定【实测】

对 PSDTO3D 自己生成的 `C:\ok3dtemp\vw1..vw13.bmp` 做**分块匹配**（48×48 块，搜索 ±90 px）：

| 项 | 实测值 |
|---|---|
| 视图尺寸 | 1200 × 1440，RGB，13 张 |
| 垂直位移 dy | **≈ 0.00**（纯水平） |
| vw1 → vw13 位移直方图 | **+38**（84 块）/ **+31**（22）/ **+18**（6）/ **+12**（8）/ **+7**（32）/ +35、+34、+9 少量 |
| 推导柱镜节距 | 1200px ÷ 3.937in ÷ 24LPI = **12.7 px/柱镜** |
| 最大位移 / 节距 | 38 / 12.7 = **2.99 ≈ 3 个柱镜** |

**关键结论**：位移不是连续分布，而是**离散的几个梯级** —— 每个梯级对应一个"深度分组"：

```
梯级 ≈ { +38, +31, +18, +12, +7 } px
对应工程里的分组/缩放： group ∈ {2,3,5}，scale ∈ {1.0, 1.5, 2.0, 2.5}
```

即：**图层按 `group` 分成若干深度平面，同组内按 `scale` 再分档**，
每个深度平面在视图序列上做**线性水平位移**，最大位移就是该梯级的值。

### 3.4 工程文件里的深度数据（实测）

`.gxwj` / `.tw3d2` 每层有两组数据：

```
第 10 … 9+N 行   每层一个整数      ← 位移基准（本工程取值 -35 … +30）
第 10+N … 9+2N 行  <angle> <group> <scale>   ← 角度 / 深度分组 / 缩放系数
```

本工程（1114，50 层）实测：

* 整数块：`0,0,0,0,30,0,0,30,0,0,20,20,0,20,30,0,10,0,0,-10,…, -35`
* `group` 分布：2 / 3 / 5；`scale` 分布：1.0 / 1.5 / 2.0 / 2.5
* `angle` 恒为 7（本工程未用）

> **待定**：整数块与 `scale` 如何共同决定 §3.3 的梯级值。
> 现有 1 组数据无法唯一确定换算（38≈30×1.27，也≈19×2.0），需要第 2 组标定点。

### 3.5 合成顺序

```
for k in 0..N-1:                      # 每个视图
    canvas = 背景
    for j in 底层 → 顶层:              # 由远及近
        canvas = alpha_composite(canvas, layer_j 平移 dx(j,k))
    view_k = canvas
```

「由远及近」很重要：视差会让各层互相遮挡关系变化，必须按深度排序叠加。

## 4. 交错合成：从 N 个视图到一张印刷图

```
for y in 0..H-1:
    for x in 0..W_out-1:
        view = 该列对应的视图号（§2 的公式）
        out[y][x] = view_images[view][y][x]
```

**必要条件**：所有视图必须**同尺寸**、且与输出**同高**（只有水平方向做交错）。
`LenticularOmega` 里就是这么校验的：

```python
if shape[:2] != (output_height, output_width):
    raise ValueError(f"TIFF 文件尺寸错误: {shape[:2]}，预期 {output_height}x{output_width}")
```

## 5. TIFF（印刷用）的要求

| 项 | 要求 | 依据 |
|---|---|---|
| 色彩空间 | **CMYK**（印刷四色；RGB 打样可用） | PSDTO3D 状态栏显示 `CMYK`；LenticularOmega 走 ICC → CMYK |
| 位深 | 8 bit/通道 | 【实测】PSDTO3D 交互文件 |
| DPI 元数据 | = **输出 DPI**（本工程 600），写进 TIFF 的 XResolution/YResolution | 决定物理尺寸，错一点整幅尺寸就错 |
| 像素尺寸 | 成品尺寸(in) × 输出 DPI；本工程 3.937in × 600 = **约 2362 px 宽** | 【推导】 |
| 交错内容 | 已按 §4 合成，**单幅**，不是多页 | — |
| 压缩 | LZW / Deflate / 无压缩均可（印刷厂通常接受 LZW） | LenticularOmega 支持 `tiff_lzw`/`tiff_adobe_deflate` |
| 对齐 | 必须与柱镜节距**相位对齐**：第 0 个柱镜的起点 = 图像左边缘（或按版面留白偏移） | 否则整幅错位 |

> **相位对齐是光栅印刷最常翻车的地方**：`P` 是小数时，必须保证
> "第一个柱镜的中心"与"第一组像素列的中心"重合，否则越往右错得越多。

## 6. PSD 输出的要求

PSDTO3D 的 `输出PSD` 应当输出 **N 个图层 = N 个视图**
（供设计师在 Photoshop 里二次编辑，或直接喂给 `LenticularOmega` 这类后置软件再交错）。

| 项 | 要求 |
|---|---|
| 图层数 | = N（13） |
| 每层内容 | 第 k 个视图（已按 §3 位移合成后的整幅） |
| 图层尺寸 | 全部 = 画布尺寸（不可裁剪） |
| 图层顺序 | 与视图顺序一致（k 递增），便于后置软件按序交错 |
| 色彩空间 | RGB 或 CMYK（与源一致） |
| 命名 | 建议 `view_01..view_13`，便于排序 |

> 【推断】PSDTO3D 的 PSD 导出可能是"每层一个视图"。需实测确认。

## 7. 能否绕过软件直接复刻？

**能，而且两段都有现成落点**：

| 阶段 | 难度 | 结论 |
|---|---|---|
| ② 交错（N 视图 → 印刷图） | 低 | **`LenticularOmega` 已完整实现**（`compute_indices`） |
| ① 视图生成（分层 PSD → N 视图） | 中 | 模型已实测确认：**纯水平线性位移 + 由远及近 alpha 合成**，参数见 §3.3 |

也就是说：**`PSDTO3D` 的可复刻部分 = ①，②你已经有工具了。**

### 复刻管线（Python）

```
1. 读 PSD 图层（psd_tools），按 y 顺序 → 由远及近
2. 读每层深度（工程文件第 9+2N 行的 <angle> <group> <scale>，或手工指定）
3. for k in range(N):
       canvas = 空
       for layer in bottom→top:
           dx = depth_j * W * (k-(N-1)/2)/(N-1)
           canvas.alpha_composite(layer, offset=(dx,0))
       save view_k.png
4. 交错（LenticularOmega）→ CMYK TIFF
```

**唯一需要标定的输入是 `W`（总视差像素）**。
本工程实测 W ≈ 37.85 px；而 `W` 与界面 `Depth` 字段的换算关系需要再测两组
（改 Depth 一次，看 W 怎么变）——这是 §8 的待验证项 1。

## 8. 对"修软件"的启示

有了上面的模型，之前逆向里那堆"神秘数字"全部有了归宿：

| 逆向量 | 实测值 | 在本模型里的含义 |
|---|---|---|
| `[-0x110]` | 1222 | = 行数(94) × 视图数(13) → 交错后**宽度的列计数** |
| `[-0x10C]` | 1474 | 另一轴的同构量（行 × 视图） |
| `[-0x124]` | 0（缺） | 通道缓冲的**行宽**，应 = 图像宽度 |
| `[-0x128]` | 1575 | 源图像宽度（PSD 宽） |
| `[-0x133]` | 13 | 视图数 N（来自对象虚方法，非配置） |
| `[-0xFC]` | 256 | 分块行数（硬编码） |

**最重要的结论**：这些量**全部可由 PSD 尺寸 + 界面参数 + LPI/DPI/N 算出**，
狗配置提供的只是"同一批数的另一份副本"。所以：

* 二进制绕过是可行的（已实测：导出从 0 字节 → 7.18MB，不再报错）
* 但更干净的路是**按本模型重写导出**，把公式写对，而不是继续猜补丁

### 待验证清单

| # | 项目 | 怎么验 |
|---|---|---|
| 1 | `W` 与界面 `Depth` 的换算 | 改 Depth 再预览，量 vw1→vw13 的 dx |
| 2 | 交错是"1 列/视图"还是"变宽 + 误差扩散" | 检查 2022 交错输出的列周期：应 ≈ P=25 而非 13 |
| 3 | PSD 导出是不是"N 层= N 视图" | 导一次 PSD，看图层数 |
| 4 | 相位对齐基准（左边缘 or 中心） | 对比柱镜板实物或厂方要求 |
