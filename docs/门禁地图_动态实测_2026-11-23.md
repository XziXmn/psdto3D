# 门禁地图（动态实测版 · 2026-11-23 14:4x）

> 方法：在仿真狗的 `CreateFileA` 桩里对**所有设备路径**打印"调用者模块+偏移"（`GATE[...]`），
> 然后跑完整流程（打开工程 → 导入 PSD → 导入设置 → 预览 → 导出 TIFF → 导出 PSD），
> 看整条链路上到底有哪些代码在碰狗。
> 开关：程序目录放 `_gate_map.txt` 即启用；日志在 `_dongle.log`。

## 一、实测结果：整条流程只有 1 处在碰狗（exe 启动时 3 次）

```
GATE[psdto3d101.exe+ED24D] open \\?\usbstor#disk&ven_usbkey&prod_usbkeyco._&rev_2.00#6&...
    × 3 次，全部发生在启动阶段
```

| 项 | 值 |
|---|---|
| 调用者 | `psdto3d101.exe+0xED24D`（VA 0x4ED24D，位于 `FUN_004ED130` 内） |
| 次数 | 3（启动时） |
| 后续流程（打开工程/导入/预览/导出 TIFF/导出 PSD） | **exe 侧零设备访问** |

⇒ **exe 只在一处问狗**，就是我们早已用回放满足的那个启动检查。

## 二、另外两处已知门禁（不在 exe 侧，故不在上面这张表里）

| 位置 | 证据 | 状态 |
|---|---|---|
| `cmyktiff2_real.dll`（导出几何 `X2`） | 它的 IAT 也被挂钩，本次流程中**没有**再开设备——它复用了已打开的假句柄 | ✅ 已注入 2336 满足 |
| `zu06.dll`（PSD 模块） | 历史日志里 **768 次** `\\.\MyUSBKey0..255`；它的 IAT 未挂钩，所以不在 GATE 表里 | ❌ 未解开 → PSD 走旁路补全 |

> `zu06` 的 IAT 一挂钩就会把 `\\.\MyUSBKey` 变成"打不开"，
> 它的参数解码随即失败、导出中途崩（多次复现），所以**不能靠挂钩去观测它**，
> 只能靠历史日志（768 次探测）+ 行为推断。

## 三、"还有没有别的门禁"—— 现在的答案

| 检查面 | 结论 |
|---|---|
| **exe 侧** | 只有 1 处（`FUN_004ED130`），已满足；全流程无第二次调用 |
| **导出库侧** | `cmyktiff2_real` 只取一个几何值（已注入）；`zu06` 有独立检查（PSD 用，已旁路） |
| **其它 DLL**（ok3d1/ok3d4/zu6/3d/8602…） | 流程中**没有任何设备访问**（GATE 表为空）；但这些模块的 IAT 未挂钩，理论上可能有"不经过 CreateFileA 的检查" |
| **注册表/卷指纹** | `zu06` 导入了 `RegQueryValueExA`、`GetVolumeInformationA`，但本次流程未见异常；未逐条验证 |

**结论**：在我们跑过的功能集里，**没有发现新的门禁**。
剩下唯一"可能漏检"的环节是 **未挂钩的 DLL 内部检查**（尤其 zu06 的注册表/卷指纹路径）。

## 四、要不要把剩下这点也堵死？

两条路（都不需要你在场）：

1. **给每个候选 DLL 单独挂一次 `CreateFileA`（只记不改）+ `RegQueryValueExA` 日志**，
   一次流程就能看全"谁问了什么"。风险：挂钩可能让个别模块行为变化（zu06 已证实会崩）。
   做法：一次只挂一个，出问题立刻回滚。
2. **接受现状**：交付包所有功能已实测可用（含 PSD 旁路），
   把这份地图作为"已知风险清单"交给实际使用者，遇到"某功能静默不生效"就回来看这份表。

## 五、怎么复现这张表

1. 程序目录放空文件 `_gate_map.txt`；
2. 跑流程；
3. `_dongle.log` 里 `grep 'GATE\['` 即可。
