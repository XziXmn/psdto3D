**第 8 轮修复了两个致命缺陷**（细节见 `README.md` 修复记录表）：

1. `Invalid numeric input`：全工程装载器 0x511408（10.1: 0x511790）的**角度块/图层行块
   循环次数**取自布局辅助函数 0x4D2F14 的计算值而非层数，行数不符后曲线解析器错位，
   把图层行的 scale 浮点（`1.00000000000000E+0000`）当整数 Val → 106 → InOutRes 中毒，
   后续每个 IOResult 检查连锁弹框，并以半残状态收尾（2022 的"画布空白"即此）。
   修复 = 两处 3 字节等长补丁，循环计数改用层数局部变量 `[ebp-0x54]`。
2. 2022 打开/导出 AV `0x5023C7`/`0x501093`：渲染校验循环读交错组表
   `[0x52309c][group-1]`，建表中途（50 层/43MB PSD 加载中泵出的重绘）拿到 nil 槽。
   修复 = 双洞穴守卫（表 nil/组越界/槽 nil/视图越界 → 按命中画出来）。

**历史误判更正**：此前"10.1 可打开工程"的记录全部发生在 PSD 与工程**不同目录**的场景，
当时程序实际是**静默拒绝**（层数/表全为默认值）—— 打开路径在此前从未真正成功过。
PSD 同目录才是程序设计的正路（第 1 行 PSD 基名在工程目录查找），也正是踩雷之处。

## 二、已经确认的技术事实（可作为后续依据）

### 2.1 工程文件是同族文本格式

| 行 | `.tw3d2`（10.1 / 2022） | `.gxwj`（99） |
|---|---|---|
| 1 | PSD 绝对路径 | 同 |
| 2 | ` LPI Angles X Depth` | 同 |
| 3 | `99100 layerCount width height` | `39550 0 0 0` |
| 4–6 | 三条横幅 | 两条横幅 |
| 6/7 | 时间戳 | 额外一个浮点（参考样本 `4.634E+0004`） |
| 7/8 | ` DPI LPI2 calc flag1 flag2` | 同（位置前移一行） |
| 之后 | layerCount 个整数 → layerCount 行 `angle group  scale` → 曲线块 | 同 |

* `tools\project_convert.py` 双向转换，**无损**：
  * `.gxwj` → 改路径后与原文件**逐字节相同（仅第 1 行不同）**；
  * `.tw3d2` → `.gxwj` → `.tw3d2` 往返除作者行/时间戳外**逐字节相同**。
* 曲线块坐标行在 `.gxwj` 里结尾是 `\r\r\n`（多一个 CR），10.1/2022 解析会报 `Invalid numeric input` → 转换时已归一化。

### 2.2 四个"隐形坑"（都已在工具里处理或记录）

| # | 坑 | 现象 | 处理 |
|---|---|---|---|
| 1 | 工程里存**绝对 PSD 路径** | 换机器即 `Can not found the specified psd file!` | `fix_project_psd.py` 自动找同名 PSD 并改写第 1 行 |
| 2 | PSD 文件名**含空格** | 10.1 报找不到；99 直接 AV | 工具会把 PSD 复制成无空格名并指向它 |
| 3 | 图层**分组号不连续**（如只有第 5 组） | 生成/导出时 `0x50A001`、`0x5023C7` 空指针 AV | `tw3d2.py regroup` / 转换时自动致密化 |
| 4 | 工作目录写死 `D:\ok3dtemp\` | `Cannot create file "D:\ok3dtemp\g1.bmp"`（无 D 盘时） | 字符串级补丁把 D:/E: 改成 C:（`patch_tempdir.py`） |

### 2.3 当前尚未解决的缺陷（按严重度）

1. **2022 导入/导出 AV `0x5023C7`**
   `mov edx,[edx+ecx*4]`，`edx = table[group-1] == NULL`。
   同一逻辑还有一份在 `0x501093`（导出路径）。说明 2022 在"建组表"与"用组表"之间存在时序/数据不一致。
2. **99 打开 50 层 CMYK 工程 AV `0x4DD84D`**
   `write to 0x2D`。99 是 2013 年构建，怀疑不支持 5 通道/50 层，或需要更旧的 `zu6.dll` 路径。
3. **10.1 偶发 `Invalid numeric input`**
   刚才用「简单工程 + 干净目录」仍复现过一次，说明除了 CR 还有别的解析点（怀疑与 `.inf` 设置合并、或第 8 行的 `flag` 值有关）。需要做**字段级二分**定位。
4. **导出 TIFF 无产出**
   加载后 "Output Sets"（输出 DPI/宽/高）为 0 时导出直接返回；需要在 UI 里设置或用消息写入这三个编辑框。

### P0 —— ✅ 已修：`Invalid numeric input`（第 8 轮，二进制层）

思路：**字段级二分**。用最小工程（3d2，12 层）逐项替换回原值，找出触发字段。

1. 以能正常打开的 `1114-1_10.1_2022.tw3d2` 为基线，与失败的 `workdir\p.tw3d2` 做 4 组对照：
   (a) 仅第 3 行（`99100 N W H`）不同；(b) 仅第 8 行（DPI/flags）；(c) 仅作者/时间戳行；(d) 仅曲线段。
2. 每组跑一次 `dialogless_launch` + 命令 3，记录是否报错。
3. 定位到行后，在 `project_convert.py` / `fix_project_psd.py` 里加对应的归一化规则。

**验收**：`workdir\p.tw3d2` 与 `1114-1_10.1_2022.tw3d2` 都能打开并渲染，无任何弹框。

### P1 —— 修 2022 的组表空指针（半天）

1. 用 `inspect_state.py` 在**导入瞬间**抓 `[0x52309c]`（组表）、`[0x5230b4]`（图层记录）、`[0x523158]`（索引）三者的实际值，确认是"表没建"还是"键越界"。
2. 若是"表没建"：找建表函数 `0x509E44` 的三个调用点（`0x504D83` / `0x5054D4` / `0x50635B`），确认导入路径是否漏调；
   必要时在 `0x5023C7` 前加"空则跳过"守卫（复用 `patch_crash_guard.py` 的洞穴方案）。
3. 若是"键越界"：在 `0x5023B4` 处把 `group` 钳到表长度内（`cmp ax, len; jbe`）。

**验收**：2022 打开 `1114.psd`（50 层 CMYK）后画布有画面；导出 TIFF 能产出非空文件。

### P2 —— 99 打开大 CMYK 工程（半天，可延后）

1. 用 99 的日志/异常地址 `0x4DD84D` 反汇编定位（`psdto3d.exe` RVA `0xDD84D`）。
2. 优先验证"层数上限"假设：把 PSD 裁到 12 层再开；若通过，则在转换工具里对 99 输出做**层数降级提示**。

**验收**：99 能打开 12 层 CMYK 工程；对 50 层给出明确提示而不是崩溃。

### P3 —— 工作目录与输出参数健壮化（1～2 小时）

1. 启动器里预创建 `C:\ok3dtemp`（`langlaunch` 里加 `CreateDirectory`）。
2. 导出前把 "Output Sets" 的 DPI/宽/高 用 `WM_SETTEXT` 写入合理值（DPI 取第 8 行、宽高取 PSD 尺寸），
   或查明这三个值从哪个设置项读取并直接写配置。

**验收**：`run_e2e.py --commands open=3,preview=12,tiff=16` 能产出 TIFF，且 `tiff_info()` 校验通过。

### P4 —— 中文默认的"去启动器化"（可选，半天）

现状靠 `langlaunch.exe` 投递命令 48/37。若要彻底默认：
1. 在 `0x523xxx` 找语言全局变量（由菜单 48 的处理器写入），把初始化值从 0 改成 1；
2. 或给 exe 打一个"启动后自动执行命令 48"的补丁（TLS 回调 / 入口点劫持）。
**验收**：直接双击 exe 即为中文。

### P5 —— 重写（长期）

见 `docs\重写方案.md`。本轮补充两条新认知：
* 工程格式已完全掌握 → 新格式的 legacy 导入器可直接复用 `project_convert.py` 的解析器；

## 五、给用户的即时操作建议

1. **用 10.1 做主力**：目前只有它能完整打开 99 构建的 PSD 并渲染。
2. 任何工程/PSD 迁移，先跑一遍：
   ```powershell
   python tools\fix_project_psd.py "工程.tw3d2" --to tw3d2
   python tools\fix_project_psd.py "工程.gxwj"  --to gxwj
   ```
   它会：找 PSD → 去空格副本 → 改路径 → 分组致密化 → CR 归一化。
3. 打开顺序建议：**先开工程**（工程里带 PSD 路径），不要先导入 PSD 再开工程。
4. 若出现 `Invalid numeric input`，把该工程发我，我按 P0 的二分法当天定位。
5. 若出现 `D:\ok3dtemp` 相关报错，确认包内 exe 已打过 `patch_tempdir.py`，并手动建好 `C:\ok3dtemp`。
