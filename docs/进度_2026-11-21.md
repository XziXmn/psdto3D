## 二、启动检查（本次新发现，已修好）

无狗启动时程序弹框并退出：

```
对话框正文：The system did not find any software key, please insert it.
```

对应代码：

```
0050300F  call 0x4d2adc            ; 设备检测
00503014  cmp  eax, 0xfffffbe3     ; 无设备时返回 -1053
00503019  jne  0x50302a
0050301B  mov  eax, 0x503f1c       ; 那条英文消息（VA 0x503F1C，长度 0x3B）
00503020  call 0x43397c            ; 弹框
00503025  call 0x404ddc            ; 退出
```

`0x4D2ADC` 用普通 `ret`（无栈参数），因此可在入口安全改为 `33 C0 C3`。

**改后实测**：`TForm1` 正常显示，44 个子控件齐全（含 `TStringGrid`）。

## 三、用户截图揭示的关键事实（最重要）

### 3.1 表格是有数据的

行 22–32 的实测显示：

| 行 | Group | Offset | cm |
|---|---|---|---|
| 22 | + | 0 | 0 |
| **23** | + | **-23333E（截断）** | 0 |
| 24 | + | 0 | 0 |
| 25 | + | 0 | 0 |
| **26** | + | **-23333E** | 0 |
| **27** | + | **-23333E** | 0 |
| **28** | + | **-23333E** | 0 |
| **29** | + | **-23333E** | 0 |
| 30–32 | + | 0 | 0 |

**五个非零行 = 23 / 26 / 27 / 28 / 29**，与真狗基准的行号**完全一致**。

### 3.2 由此得到的两条结论

1. **网格存储与读取都正常**。此前判断"格子读不出来/网格是空的"是错的。
2. **Offset 的数值是错的**。应是 `-5`，实际显示 `-23333E`（被列宽截断，完整值待测）。

### 3.3 cm 列

全部为 `0`，不是 `-0.04`。与"cm 依赖 Offset 数值"一致——Offset 都错了，cm 自然不对。

## 五、Offset 数值错误的可能原因（待验证，不是结论）

`-23333E` 若完整值是 `-233336` 或更大，与 `-5` 的比值不是 2 的幂，也不是 10000 的整数倍。
可能的来源：

1. 桩里 `[ebp-0x48]`（缩放 10000.0）只是显示端缩放，真正的原始值另有来源；
2. `[0x523190]`（18000）或 `[0x523074]`（25400×31）参与了 Offset 的计算，而我们设错了；
3. 流读取得到的 raw 本身不是 -5，我们从未真正读出过它（此前只用"长度 17"推断）。

**下一件事就是把 `0x511A73` 处栈上的字符串完整打印出来**，看清真实数值与长度。
